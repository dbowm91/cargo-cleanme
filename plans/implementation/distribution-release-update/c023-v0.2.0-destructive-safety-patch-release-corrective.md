## 1. Objective

Correct two destructive defects that are present in the immutable published
0.2.0 bytes, requalify the post-release fixes already on `main`, repair the
planning/closure state that incorrectly treats M013 as fully closed, and publish
an immutable patch release that replaces 0.2.0 as the recommended version.

The two safety defects are independent and both violate existing canonical
contracts:

1. **Pre-subcommand `--dry-run` could execute a real cleanup.**

   The accepted CLI spelling:

   ~~~text
   cargo cleanme --dry-run clean ROOT
   ~~~

   parsed successfully in 0.2.0, but the root-level flag was discarded by the
   `Clean` arm. Execution fell through to `CleanMode::Execute`, spawned a real
   `cargo clean`, reported success, and returned exit 0.

   The long-term specification requires canonical `--dry-run` simulation to
   invoke **zero** Cargo clean processes.

2. **A cleanup root could contain another resolved workspace's source tree and
   still be classified `PrivateBounded`.**

   The ownership classifier checked source overlap only against the group
   owner's members. If workspace A's declared output root contained workspace
   B's source tree, A's output could still be treated as private and cleaned.
   A real Cargo clean on A could therefore delete B's `Cargo.toml`,
   `Cargo.lock`, `src/`, and other source content with exit 0.

   `PrivateBounded` is valid only when the destructive region is disjoint from
   **all** resolved workspace source trees in the cleanup ownership universe.

Both defects were found only after 0.2.0 publication. Because that release is
immutable, C023 must not replace its assets or move its tag. The remedy is a new
patch release.

## 2. Why previous verification missed the defects

### 2.1 Dry-run flag placement

M012A proved the intended simulation semantics but did not cover the Cartesian
product of:

- root-level flag before the subcommand;
- subcommand-local flag after the subcommand;
- Cargo plugin invocation spelling;
- `clean` versus `update`;
- simultaneous simulation and Cargo-preview selectors.

The parser accepted the root-level spelling, so help/parse tests looked valid,
while dispatch read only subcommand-local fields. The missing premise was not
"does clap accept the flag?" but "does every accepted spelling reach the same
execution mode?"

### 2.2 Neighbour source ownership

C003/C004/C006 and M012A extensively tested a workspace against its **own**
source tree and against overlapping output roots. They did not assert the
cross-workspace invariant:

~~~text
output region owned by A
contains source tree owned by B
=> never PrivateBounded
~~~

The classifier's local-owner check therefore passed all single-workspace source
overlap tests while the global ownership universe remained incomplete for this
specific hazard.

### 2.3 Release smoke scope

M013's public updater smoke verified installation/update identity and
Cargo-managed refusal. It did not execute adversarial cleanup fixtures against
the published binary, so it could not detect these cleanup semantics.

C023 adds published-binary premise tests for the defect shapes before allowing
the patch release to close.

## 4. Severity and release policy

These are not ordinary correctness bugs.

- The dry-run defect violates an explicit no-mutation request.
- The ownership defect can delete source files belonging to a different
  project.

Treat 0.2.0 as a **known unsafe release for destructive operation**.

Repository policy under C023:

1. Never replace or mutate the immutable GitHub v0.2.0 release/tag/assets.
2. Add an explicit 0.2.0 safety warning to current repository documentation.
3. Publish 0.2.1 through the full immutable release process.
4. **Yank crates.io 0.2.0** as a safety measure. Prefer doing this as soon as an
   authorized operator begins C023; if operational policy requires a replacement
   to exist first, it must happen immediately after 0.2.1 is public and
   verified. Record the actual ordering.
5. A yank is not deletion: retain 0.2.0 history and evidence. Do not pretend it
   never shipped.
6. Do not un-yank 0.2.0 unless a future explicit decision explains why exposing
   a release with these destructive defects is acceptable.

The historical 0.1.x non-yank rationale does not apply here. Those entries
described updater defects with bounded behavior; 0.2.0 can violate dry-run and
delete another project's source.

## 5. Work package A — Reproduce both defects against published v0.2.0

Before accepting the fixes, create isolated disposable premise fixtures that
exercise the **published** 0.2.0 binary.

No premise test may run against a real developer project.

### A1. Pre-subcommand dry-run premise

Create a temporary Cargo project with:

- a known target artifact;
- timestamps/policy chosen so the project is otherwise eligible;
- a fixture/logging mechanism sufficient to prove whether Cargo clean ran.

Run the exact affected spelling with published 0.2.0:

~~~text
cargo-cleanme --dry-run clean <fixture-root>
~~~

or the Cargo-plugin equivalent after proving argv normalization is identical.

Required premise evidence:

- 0.2.0 accepts the command;
- the target/artifact state changes or a real Cargo clean invocation is
  otherwise authoritatively observed;
- exit/output shows the command believed it succeeded;
- the fixture, not an unrelated failure, caused the observation.

Then run the fixed candidate and require:

- zero Cargo clean subprocesses;
- target bytes unchanged;
- simulation/would-clean output;
- successful simulation exit semantics.

### A2. Neighbour-source premise

Construct two real temporary Cargo workspaces/projects:

~~~text
outer/
  Cargo.toml
  .cargo/config.toml -> target-dir = outer/out
  out/
    inner/
      Cargo.toml
      src/...
~~~

The exact shape may differ to match Cargo's real output-resolution mechanics,
but these premises must hold:

- outer's resolved output covering region contains inner's source root;
- inner is independently resolved in the same ownership universe;
- inner's own output location does not accidentally make the test fail for a
  different reason;
- a cache marker/activity setup does not mask the ownership defect.

Against published 0.2.0, demonstrate in a disposable copy that the dangerous
region can reach the destructive path and that inner source content is removed
or otherwise authoritatively shown to be exposed.

Against the fixed candidate require:

- the region is never `PrivateBounded`;
- diagnostic identifies that the output contains a workspace source tree;
- zero real Cargo clean processes for that cleanup unit;
- inner `Cargo.toml`, lockfile, config, and source marker remain byte-identical.

The published-binary premise evidence may be produced once and retained. Never
repeat destructive proof outside an isolated temp fixture.

## 6. Work package B — Review and harden the dry-run fix

Do not accept the current implementation only because the original spelling now
works.

Build a dispatch matrix covering every accepted relevant spelling:

### Cleanup simulation

- `cargo-cleanme --dry-run`
- `cargo-cleanme --dry-run clean ROOT`
- `cargo-cleanme clean --dry-run ROOT`
- historical `--dryrun` alias where still accepted
- Cargo plugin argv spelling `cargo cleanme ...`

For every simulation spelling:

- resolved mode is `Simulate`;
- zero Cargo clean subprocesses are spawned;
- output reports would-clean/estimated bytes, not recovered bytes;
- exit semantics match normal simulation.

### Preview precedence

Cover:

~~~text
cargo-cleanme --dry-run clean --cargo-preview ROOT
cargo-cleanme clean --dry-run --cargo-preview ROOT
~~~

Simulation must win because it is the stricter zero-Cargo-clean mode.

### Update dry-run

Cover accepted root/subcommand spellings of updater dry-run and prove they
reach the same non-mutating updater path.

Do not make clap's root flag `global = true` if that recreates the documented
argument-id collision. Preserve one explicit reconciliation point.

### Invalid/ambiguous combinations

If a spelling cannot have a coherent public meaning, reject it at parse time
with a focused test rather than silently selecting Execute.

## 7. Work package C — Review and harden the global source-disjointness fix

The ownership proof must be global to the selected resolved workspace universe.

Required invariant:

~~~text
For every destructive covering root R:
    for every resolved workspace member source root S:
        contains(R, S) => ownership != PrivateBounded
~~~

This must hold regardless of whether S belongs to an owner of the physical
output group.

Required layers:

1. **Classification layer**
   - `build_groups` cannot emit `PrivateBounded` for a covering region
     containing any resolved source root.

2. **Final preflight layer**
   - immediately before Cargo spawn, the cleanup unit must independently refuse
     if fresh resolved source ownership shows a neighbouring source inside the
     destructive region.

The second proof is required even if the classifier already rejects the group.
It protects against stale/intermediate classification and future refactors.

Cover:

- neighbour source directly under covering root;
- neighbour source multiple levels below;
- multiple neighbours;
- own source tree;
- conventional source directories;
- equal paths;
- canonicalized/symlink spellings without following unsafe symlink directories;
- unrelated sibling workspaces remain eligible when all other proof succeeds.

Do not weaken complete ownership resolution to make the new all-workspace check
cheaper.

## 19. Acceptance criteria

C023 closes only when:

- both destructive 0.2.0 defects are reproduced authoritatively in disposable
  fixtures or equivalent published-binary evidence;
- the dry-run fix covers every accepted root/subcommand placement and guarantees
  zero Cargo clean subprocesses;
- simulation wins over preview in ambiguous accepted combinations;
- `PrivateBounded` source disjointness is proven against every resolved
  workspace, not only the owner;
- final preflight independently protects neighbouring source trees;
- the current macOS `dua_core::FileType` CI regression is corrected without
  skipping platform coverage;
- all interrogation-pass changes included in the patch are requalified;
- regression tests exercise actual CLI/Cargo resolution paths, not only private
  helper state;
- planning/docs accurately mark 0.2.0 affected and M013 historical closure as
  corrected by C023;
- final pre-tag local and hosted gates are completely green;
- v0.2.1 is published on GitHub and crates.io from one exact source;
- v0.2.1 is immutable and all contracted assets match its attestation;
- the **automatic** v0.2.1 post-release smoke passes all five target lanes;
- published v0.2.1 passes both destructive safety fixtures;
- crates.io 0.2.0 is yanked;
- M011C is upgraded from conditional only if the automatic trigger evidence is
  actually green;
- no medium-or-higher unresolved finding remains that can invalidate destructive
  safety or release identity.

## 20. Stop conditions

Stop before tagging if:

- either destructive defect cannot be reproduced as described and the diagnosis
  is therefore incomplete;
- current fixes only mask the fixture instead of establishing the canonical
  invariant;
- any hosted CI lane remains red/cancelled;
- another destructive or high-severity defect appears;
- patch contents cannot be cleanly separated from an intentional breaking
  behavior change.

Stop publication if:

- tag/source/version/changelog identity disagrees;
- Eggpack or automatic staged validation is not green;
- draft bytes differ from qualified bytes;
- immutable-release policy is unexpectedly disabled.

After v0.2.1 publication, do not claim C023 fully closed if:

- automatic M011C fails;
- attestation verification fails;
- either public-binary safety fixture mutates unexpectedly;
- crates.io package/source identity differs from the GitHub release.

A defect in immutable 0.2.1 bytes requires a new corrective/patch release. Never
replace the published assets.
