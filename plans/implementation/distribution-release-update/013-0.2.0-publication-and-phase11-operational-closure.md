## 1. Objective

Publish `cargo-cleanme 0.2.0` from one exact reviewed source commit and use that
release to close the remaining real-world Phase 11 evidence.

This milestone is deliberately operational. The release machinery already
exists. M013 must exercise it without bypasses and record whether its premises
hold in production.

The intended end state is:

- GitHub release `v0.2.0` published and immutable;
- crates.io `cargo-cleanme 0.2.0` published from the exact release tag;
- all contracted release assets attested and digest-verified;
- staged validation green before publication;
- automatic post-publication smoke green across all five contracted targets;
- C018 released-binary Cargo-owned refusal proven for default Cargo home and
  `cargo install --root`;
- M011A/M011B/M011C/C018 closure records updated with actual release evidence;
- registry/publication state reconciled.

## 2. Irreversibility boundary

Publication is the irreversible boundary.

Before the GitHub draft is published:

- a bad draft may be discarded/rebuilt from a corrected release commit/tag as
  repository policy permits;
- no evidence may be converted into a pass by manual prose.

After publication:

- immutable release assets/tag must never be replaced;
- a product/release defect requires a corrective and a new patch release;
- failed original smoke/attestation evidence remains recorded even if a rerun
  later passes.

Never disable immutable releases to repair a bad publication.

## 3. Release identity

The version is already selected:

```text
Cargo.toml = 0.2.0
tag        = v0.2.0
```

Before creating the tag:

1. C022 must be closed.
2. The final release commit must contain the complete 0.2.0 changelog entry.
3. Replace `## [Unreleased]` release content with
   `## [0.2.0] - YYYY-MM-DD` as appropriate for actual publication
   preparation, retaining a fresh empty `[Unreleased]` section if that is the
   repository convention.
4. `Cargo.toml`, `Cargo.lock`, changelog identity, and tag must agree.
5. The working tree must be clean.

Do not tag a planning-only commit and then publish crate bytes from a later
`main`.


Required pre-tag/pre-stage evidence:

- Release drift guard green;

  `python3 scripts/verify-release-attestation.py --settings-only`.

If any source file, dependency, generated artifact, changelog content, or
release contract changes after the release check, the evidence is stale.
Re-run the complete gate and re-establish exact identity before staging.

## 6. Work package C - Stage the draft with Eggpack

## 10. Work package G - Publish crates.io from the exact tag

Publish from a detached checkout/worktree of `v0.2.0`, never from a moving
`main`:

```text

cd /tmp/cargo-cleanme-publish
python3 scripts/check-release-identity.py --tag v0.2.0

```

Before `cargo publish`:

- verify the detached checkout is exactly the tag;
- run the identity check;
- optionally repeat `cargo publish --locked --dry-run` if any environmental

After publication, verify crates.io exposes exactly `0.2.0`.

If crates.io rejects publication after GitHub release publication, do not
replace GitHub assets. Fix the publication problem if it is operational; if the
crate bytes/source identity need to change, open a corrective/new version.

## 12. Work package I - Require automatic M011C five-target smoke

The `release: published` event must automatically launch
`post-release-smoke.yml`.

Required transition:

```text
v0.1.6 -> v0.2.0
```

The resolver must independently derive the previous stable release rather than
being told to use v0.1.6 by the operator.

Required evidence:

- crates.io wait resolves `to_version=0.2.0`;
- all five contracted target lanes run;
- no fail-fast hides remaining lanes;
- self-managed updater reaches 0.2.0 and final bytes equal the public target
  asset;
- post-update dry run is correct;
- Cargo-managed installation refuses mutation and leaves bytes unchanged.

Record the automatic run id and each target conclusion.

A manual rerun may demonstrate recovery from transient infrastructure, but the
original automatic result remains in the closure record.

## 13. Work package J - Complete C018 real-release provenance evidence

Using the published 0.2.0 target, exercise an older published Cargo-managed
installation so the updater has a newer version available.

### Default Cargo home

Install an older published cargo-cleanme through normal `cargo install`, then
invoke its updater with 0.2.0 available.

Required:

- updater refuses replacement for Cargo-managed ownership;
- bytes remain unchanged;
- Cargo bookkeeping remains unchanged;
- refusal names the correct Cargo reinstall/update action;
- locally forbidden provenance causes no release-asset mutation.

### Explicit --root

Install the older version with:

```text
cargo install cargo-cleanme --version <previous> --locked --root /tmp/root
```

Exercise the same update refusal.

Required:

- `/tmp/root/bin/cargo-cleanme` bytes unchanged;
- `cargo install --list --root /tmp/root` remains coherent;
- no manager-owned file replacement.

Use exact published versions and public authorities.

Do not confuse "already current" with provenance refusal; the starting version
must be older than 0.2.0 so the mutation path would otherwise be reachable.

## 14. Work package K - External install/CLI smoke for the breaking 0.2.0 boundary

From outside the repository, exercise the public installers/package sufficiently
to confirm the release users receive has the intended 0.2.0 front door.

At minimum on representative supported hosts:

- bare `cargo cleanme` is the new Routine Execute entry point, exercised only

- `cargo cleanme scan --known` remains Routine read-only;
- `--format log` emits one bounded line;
- `--format json` remains parseable.

Do not run destructive examples against an uncontrolled developer tree.

## 17. Failure semantics

### Before GitHub publication

Any failed qualification means **do not publish**.

Fix the defect, create a new release commit if source changes, re-establish tag
identity before publication, and restart qualification.

### After GitHub publication

The release is immutable.

- Never replace an asset.
- Never move/recreate the published tag.
- Never disable immutability as a workaround.
- Record the failure.
- If product/release bytes are defective, open a corrective and publish a new
  patch release.
- If only external infrastructure failed, preserve the failed receipt and use a
  documented rerun to show recovery.

## 18. Acceptance criteria

M013 closes only when:

- C022 is closed;
- exact release commit/tag/source/version/changelog identity is proven;
- Eggpack staged all contracted assets from that exact source;
- automatic M011B staged validation passed before publication;
- human draft inspection passed;
- GitHub `v0.2.0` is published and immutable;
- crates.io `0.2.0` is published from the exact tag;
- M011A release+asset attestation verification passed;
- automatic M011C five-target smoke passed;
- C018 default-home and `--root` released-binary refusal evidence passed;
- external public installation/CLI smoke confirms the 0.2.0 breaking boundary;
- all four Phase 11 conditional/release-evidence records are reconciled;
- no medium-or-higher unresolved finding remains that invalidates the published
  release.

## 19. Stop conditions

Stop before publication if:

- C022 is not closed;
- any required hosted gate is incomplete/cancelled/red;
- tag/source/version/changelog identity disagrees;
- the staged validator did not trigger automatically or is not bound to the
  exact upstream source;
- draft inventory/digests differ from the contract;
- immutable release policy is unexpectedly disabled.

After publication, stop any claim of successful closure and open a corrective if:

- attestation verification fails;
- any automatic smoke lane exposes a product/release defect;
- C018 real Cargo-managed refusal mutates bytes or bookkeeping;
- crates.io package identity differs from the GitHub release/tag source.

## 20. Non-goals

- add new release targets;
- change the updater transport;
- add independent maintainer signing, SLSA, or SBOM attestations;
- change the Phase 12 CLI;
- repair the 257 opaque architecture citations;
- add CI concurrency policy;
- redesign release automation to remove the human publication gate.

Those remain independent follow-up work.
