## Known limitations and deferred work

- **No runtime ABI evidence.** The glibc 2.17 floor is declared and toolchain
  pinned, but M010A performs no release run. Runtime qualification of the exact
  release bytes is M010B's scope, and the README deliberately refuses to
  advertise the floor until then. `scripts/check-release-contract.py` fails the
  build if the README starts claiming it prematurely.
- **No public wrapper yet.** `installer-presentation.json` names
  `packaging/install.sh` and `packaging/install.ps1`; those land in M010B. The
  generated `stage` job composes them, so the release workflow's staging step
  depends on M010B. This is the declared M010A → M010B interface dependency, and
  no release may be staged before M010B closes.
- **No packaging payload check yet.** M010A validates the presentation's
  internal consistency; wrapper existence, executable bits, and
  wrapper-to-contract mapping are M010B's
  `scripts/check-installer-contract.py`.
- **No self-updater.** M010C.
- **No completions, manpage, benchmarks, or publication.** M010D.
- **Upstream producer pin.** Eggpack is pinned to a Git revision rather than a
  registry release because no registry publication is qualified. If Eggpack
  publishes a CLI, the pin can move to a version.
